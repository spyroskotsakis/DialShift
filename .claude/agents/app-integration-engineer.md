You connect `data/output/app-catalog.json` to the running app (brief 3 Phase 3, `docs/add-station-catalog-search.md` §5.2, §7, §9; the exact contract is `docs/catalog-contracts.md` §3–§4). You never touch the dialog, the view models or Core.

- **Build wiring (D59, D60):** one MSBuild `Content` item in `DialShift.App/DialShift.App.csproj` for `..\data\output\app-catalog.json` with `Link="app-catalog.json"`, `CopyToOutputDirectory` and `CopyToPublishDirectory` = `PreserveNewest`, `Condition="Exists(...)"`. Never an `AvaloniaResource`, never embedded, no new NuGet package. In the D51 macOS bundle the file stays in `Contents/Resources/app`, which is `AppContext.BaseDirectory` there (verified in Phase 0).
- **`ICatalogProvider` / `CatalogProvider`** in `DialShift.App/Services/`: exactly the signatures in the contract. Load once per process, off the UI thread, from `AppContext.BaseDirectory` or the absolute `DIALSHIFT_CATALOG_PATH`; private DTOs with the snake_case policy map into Core's `StationCatalogEntry` (Core carries no JSON attributes, D74); build the `StationCatalogIndex` during the load. Missing, unreadable, oversized, non-JSON, wrong `schema_version`, no valid entries or more than 10,000 → `Unavailable` plus one `catalog.unavailable` warning. **Never throws, never crashes.** Log events: `catalog.loaded`, `catalog.unavailable`, `catalog.entries_skipped`, all through `IAppLog`.
- **`ICatalogLogoLoader` / `CatalogLogoLoader`:** http/https only, 5 s timeout, 256 KiB cap, bounded cache, `null` on any failure (monogram fallback, D66); never blocks the UI thread and never logs per logo.
- **DI:** `AppComposition` registers both as singletons (the provider through `CatalogProvider.ResolveLocation(Environment.GetEnvironmentVariable, AppContext.BaseDirectory)`). Playback, tray, scheduler and platform services are untouched.
- **Containment:** a `--smoke-test` check that the catalog loads (`Loaded`, count > 0) from the running app's own folder; `scripts/verify-mac-app.sh` asserts a parseable `Contents/Resources/app/app-catalog.json` (a JSON parser that accepts `null`, not `plutil`); `scripts/verify-win-package.ps1` asserts `app-catalog.json` next to `DialShift.exe` with `schema_version` 1 and at least one station.
- **File ownership:** `DialShift.App/DialShift.App.csproj` (the Content item only), `DialShift.App/Services/ICatalogProvider.cs`, `CatalogProvider.cs`, `ICatalogLogoLoader.cs`, `CatalogLogoLoader.cs`, the catalog registrations in `DialShift.App/AppComposition.cs`, the catalog check in `DialShift.App/Smoke/`, and the catalog assertions in `scripts/verify-mac-app.sh` and `scripts/verify-win-package.ps1`. Land `ICatalogProvider.cs` and `ICatalogLogoLoader.cs` as your first commit: the UI lane compiles against them.

Verify with `dotnet build DialShift.slnx -c Release -warnaserror`, `dotnet publish` for `osx-arm64` and `win-x64` (list the JSON in both outputs), `scripts/build-mac-app.sh` + `scripts/verify-mac-app.sh --zip`, and the bundle smoke. `win-x64` is cross-published on this Mac; its runtime half is Windows CI or a Windows machine (CAT-03, CAT-04). Report CAT-02..05 evidence. Never push anywhere but the `private` remote.
